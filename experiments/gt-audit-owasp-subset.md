# OWASP-Subset Ground Truth Audit

**Date:** 2026-07-06
**Baseline:** `extract-runs/risk-selected_20260701_131854/` (27 policies, gemma-4-26b-a4b-it)
**Baseline OWASP Subset:** P=0.507, R=0.810, F1=0.623

## Summary

Audited all 27 policies to determine whether spurious OWASP-mapped risks (extracted but not in ground truth) represent genuine GT gaps or pipeline over-extraction. Each proposed fix was independently verified by an adversarial agent that read the policy PDF and defaulted to REJECT.

| Metric | Count |
|--------|-------|
| Total spurious OWASP risks audited | 338 |
| **Confirmed GT gaps** | **59** |
| Rejected (cross-taxonomy redundancy) | ~140 |
| Rejected (generic list, no concrete AI scenario) | ~80 |
| Rejected (evidence mismatch) | ~50 |
| Rejected (other) | ~9 |

**Key finding:** Most spurious extractions (~82%) are correctly rejected by this audit. The pipeline is over-extracting data-type variants from generic lists and cross-taxonomy duplicates. However, 59 genuine GT gaps exist and should be fixed to get honest baseline numbers.

## Rejection Patterns

The 279 rejected proposals fall into clear categories:

### 1. Cross-taxonomy redundancy (~50%)
Same evidence already covered by an existing GT entry under a different taxonomy prefix that maps to the same OWASP LLM category. Example: `ai-risk-taxonomy-generating-or-promoting-misinformation` rejected when `atlas-hallucination` + `credo-risk-021` already cover the same misinformation evidence under `llm092025-misinformation`.

### 2. Generic lists without concrete AI scenarios (~29%)
A protected attribute (race, gender, age, etc.) or data type (PHI, FERPA, PCI DSS) appearing in a parenthetical list or glossary definition, without the policy describing a concrete AI classification, inference, or processing scenario for that specific attribute. These are anti-discrimination principles, not AI risk scenarios.

### 3. Evidence mismatch (~18%)
The evidence supports a related-but-distinct risk better than the proposed one. Common patterns:
- Input-side evidence (prohibiting data entry into AI) cited for output-side risks (AI generating/disclosing data)
- Discrimination evidence cited for data-lifecycle risks (collection/processing/disclosure)
- Data quality/bias evidence cited for data contamination or curation risks
- Authorized use cases cited as evidence for unauthorized processing

### 4. Other (~3%)
Pipeline bugs (mangled risk IDs), evidence from bibliography entries, etc.

## Impact Estimate

Adding 59 confirmed risks to GT will:
- Reduce measured spurious count by 59 (from ~332 to ~273 for the OWASP subset)
- Leave measured precision roughly unchanged or slightly improved (depends on how many of these 59 the pipeline actually extracted)
- Not affect recall (these were already extracted)
- Net effect on OWASP subset F1: modest improvement from honest baseline, probably P ~0.55-0.60 → F1 ~0.65-0.70

The remaining ~273 spurious risks are genuine over-extraction that should be addressed via:
1. Variant grounding prompt tightening (reduce data-type variant spam)
2. Cross-taxonomy deduplication at extraction time
3. Generic-list detection to avoid promoting risks from glossary definitions
